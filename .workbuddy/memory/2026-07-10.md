## 修复：双击「启动伴读.cmd」打不开
- 现象：双击 .cmd 后无反应 / 停在错误页，浏览器不打开。
- 根因：双击由 Windows 资源管理器启动 cmd.exe，继承的是登录会话 PATH；该环境里没有 npm（WorkBuddy 的 managed node 在用户目录，不在系统 PATH）。原脚本首行 `where npm` 失败 → 报错 `pause` 退出，表现为“打不开”。
- 验证：直接用 `node node_modules/vite/bin/vite.js` 与系统 `C:\Program Files\nodejs\npm.cmd` 都能正常启动 Vite（localhost:5180 返回 HTTP 200），代码与依赖本身没问题。
- 修复：重写 `启动伴读.cmd`，npm 定位改为「PATH 探测 → 常见安装路径探测（%ProgramFiles%\nodejs\npm.cmd、%LOCALAPPDATA%\npm、managed node 的 npm.cmd）」，不再依赖系统 PATH 里有 npm。
- 备注：Bash 调用 cmd.exe 被安全策略拦截；本机 PowerShell 工具输出异常（疑似工具 bug），改用 Bash + 系统 npm 直接验证链路。

## 修复：随文注释生成报错"模型输出无法解析为注释列表"
- 现象：生成随文注释失败，提示"模型输出无法解析为注释列表，请重试"。
- 调用链：`readerStore.generateChapterHints` → `parseHintsOutput`（`src/services/hints/parse.ts`）→ 返回空数组 → `readerStore.ts:402` 抛错。
- 根因：prompt 的 JSON 契约 `HINTS_FORMAT_CONTRACT`（`src/services/ai/prompts.ts`）字段名约束太弱、无完整范例无反例，模型易自创字段名（note/anchor 等）；而 `parse.ts:coerce` 只认 `o.target.exact` 与 `o.text`，字段名一错整批静默丢弃 → 空数组 → 报错。报错又笼统不区分"没输出 JSON / 字段不匹配"，且原始输出 `acc` 直接丢弃无法事后排查。
- 修复：
  1. 重构 `HINTS_FORMAT_CONTRACT`：明确字段名硬约束（禁用 note/content/anchor/quote）、补 inline+block 两个真实范例、强调 exact/text 非空否则丢弃。
  2. 改 `readerStore.ts` 报错诊断：解析得 0 条时 `console.error` 打印原始输出长度与前 300 字，并按是否含 `{}` 区分"未输出 JSON / 字段不匹配"给出不同提示。
- 验证：`npm run build` 通过（877 模块，3.05s）。`::highlight` lint 警告为既有 Chromium 专有特性噪声，非本次引入。
- 提示：prompt 文件在 `src/services/ai/prompts.ts`，解析在 `src/services/hints/parse.ts`，触发在 `src/stores/readerStore.ts:generateChapterHints`。
